目录文件相关

ls -l <目录名>这是查看指定目录下的所有文件的详细信息。

ls -dl <目录名>这是查看指定目录本身的详细信息。

ls -Rl递归查看详细信息。

which <命令>查看命令所在的位置。

cp -r <目录名>拷贝目录。如果加-a就会拷贝所有属性，也就是创建时间之类的也会拷贝过去。

tac <文件名>和cat <文件名>是反过来显示文件。

wc计算文件的 Byte 数、字数、或是列数，若不指定文件名称、或是所给予的文件名为“_”，则wc指令会从标准输入设备读取数据。-c或-bytes 或-chars 只显示 Bytes 数。-l 或-lines 只显示列数。-w或-words 只显示字数。

od -tcx file1-t 指定数据的显示格式，主要的参数有:
CASCII字符或反斜杠序列
d[SIZE]有符号十进制数,每个整数SIZE字节。
f[SIZE]浮点数,每个整数SIZE字节。
0[SIZE]八进制(系统默认值为02),每个整数SIZE字节。
u[SIZE]无符号十进制数,每个整数SIZE字节。
x[SIZE]十六进制数,每个整数SIZE字节。

du查看某个目录的大小，以M为单位。

df查看磁盘使用情况。

ln -s <源文件> <目标文件>创建软连接，这样移动就不对了，要用源文件的绝对路径。

ln <源文件> <目标文件>创建硬连接，文件是同步的，指向相同的inode，删除硬连接的话其实是将硬连接计数-1。

进程共享

父子进程之间在fork后。有哪些相同，那些相异之处呢?

父子相同处：全局变量、.data、.text、栈、堆、环境变量、用户 ID、宿主目录、进程工作目录、信号处理方式…

父子不同处:

  1. 进程ID
  2. fork 返回值
  3. 父进程 ID
  4. 进程运行时间
  5. 闹钟(定时器)
  6. 未决信号集。

似乎，子进程复制了父进程 0-3G用户空间内容，以及父进程的PC，但pid不同。真的每fork一个子进程都要将父进程的0-3G地址空间完全拷贝一份，然后在映射至物理内存吗？

当然不是！父子进程间遵循读时共享写时复制的原则。这样设计，无论子进程执行父进程的逻辑还是执行自己的逻辑都能节省内存开销。

【重点】父子进程共享：

  1. 文件描述符(打开文件的结构体)

  2. mmap 建立的映射区(进程间通信详解)，

进程回收

在 Linux 进程管理中，wait和 waitpid都是用于回收子进程的系统调用。

特性 wait waitpid
等待目标 任意一个子进程终止 指定 PID 的子进程（或任意子进程）
灵活性 只能等待第一个终止的子进程 可精确控制等待哪个子进程
阻塞行为 总是阻塞等待 支持阻塞（默认）和非阻塞（WNOHANG）
使用场景 简单场景（如 Shell 单命令等待） 复杂场景（如多进程管理、服务器编程）

对于waitpid的阻塞回收和非阻塞回收区别如下：

特性 阻塞回收 (waitpid(pid, &status, 0)) 非阻塞回收 (waitpid(pid, &status, WNOHANG))
父进程行为 暂停执行，直到子进程终止 立即返回，不阻塞
返回值 成功返回子进程 PID；失败返回 -1 子进程已终止返回 PID；未终止返回 0；错误返回 -1
资源占用 父进程 CPU 闲置 父进程需主动轮询，占用 CPU 时间
代码复杂度 简单直接 需处理轮询逻辑
适用场景 单任务同步等待 多任务并发或避免阻塞

这里waitpid可以用信号处理函数，主线程不需要去轮询处理回收事件，适用于高性能需求。
