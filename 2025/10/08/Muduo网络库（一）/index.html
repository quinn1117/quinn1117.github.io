阻塞、非阻塞、同步、异步

典型的一次IO的两个阶段：数据准备和数据读写

网络IO阶段一：数据准备

系统api同步IO接口recv()

阻塞

调用IO方法的线程进入阻塞状态。

recv()默认是阻塞的，调用阻塞IO时，sockfd没有数据到来（内核TCP接受缓冲区无数据），会一直等待数据到来。

非阻塞

不会改变线程状态，通过返回值判断。

如果是非阻塞，sockfd没有数据到来，它会立刻返回。

size == -1：发生错误，需要关闭sockfd

size == -1 && errno == EAGAIN或EWOULDBLOCK：连接正常，但是没有数据，非阻塞返回

size == 0：网络对端关闭连接

size > 0：数据返回

网络IO阶段二：数据读写

注意：这里提及的是IO的同步和异步，并不是业务上并发的同步和异步。

同步

当应用程序调用同步IO接口时，网络IO阶段一数据准备好了以后，应用程序自己负责将TCP接收缓冲区内容移到内存中，这是同步。recv()是同步的IO接口。

异步

当应用程序调用异步IO接口时，可以做自己的事情，由操作系统将数据放入应用程序准备好的用户空间内存，并标记信号通知应用程序或者通过回调函数。

异步IO接口

Node.js：基于异步非阻塞模式的高性能服务器

在处理IO的时候，阻塞和非阻塞都是同步IO，只有使用特殊的API时才是异步。

同步 阻塞 非阻塞 (I/O多路复用)
阻塞 I/O select / poll / epoll
异步 Linux Windows .NET
AIO IOCP BeginInvoke/EndInvoke

业务层面的一个逻辑处理，是同步还是异步??
A操作等待B操作做完事情，得到返回值，继续处理。
A操作告诉B操作它感兴趣的事件以及通知方式，A操作继续执行自己的业务逻辑了；等B监听到相应事件发生后，B会通知A，A开始相应的数据处理逻辑。

一个典型的网络IO接口调用，分为两个阶段，分别是“数据就绪”和“数据读写”，数据就绪阶段分为阻塞和非阻塞，表现的结果就是，阻塞当前线程或者直接返回。

同步表示A向B请求调用一个网络IO接口时（或者调用某个业务逻辑API接口时），数据的读写都是由请求方A自己来完成的（不管是阻塞还是非阻塞）；异步表示A向B请求调用一个网络IO接口时（或者调用某个业务逻辑API接口时），向B传入请求的事件以及事件发生时通知的方式，A就可以处理其他逻辑了，当B监听到事件处理完成后，会用事先约定好的通知方式，通知A处理结果。

Linux五种IO模型

阻塞blocking

应用进程read->系统调用->内核数据未准备好->等待数据->数据准备好->应用程序将数据从内核空间拷贝到用户空间->拷贝完成->应用处理数据

非阻塞non-blocking

应用进程read->系统调用->内核数据未准备好->判断EAGAIN反复调用->等待数据->数据准备好->应用程序将数据从内核空间拷贝到用户空间->拷贝完成->应用处理数据

IO复用IO multiplexing

进程阻塞于select/poll/epoll，等待套接字变为可读->系统调用->数据未准备好->等待数据->数据准备好->返回可读fd->应用程序read->系统调用->应用程序将数据从内核空间拷贝到用户空间->拷贝完成->应用处理数据

也是同步IO接口

可以监听多个套接字

信号驱动signal-driven

应用进程注册SIGIO的信号处理程序，系统调用sigaction->内核返回注册状态->内核数据未准备好->应用程序继续执行自己任务->数据准备好->通知SIGIO->执行信号处理程序->应用程序read->系统调用->应用程序将数据从内核空间拷贝到用户空间->拷贝完成->应用处理数据

内核在第一个阶段是异步的，在第二个阶段是同步的；与非阻塞IO的区别在于它提供了消息通知机制，不需要用户进程不断的轮询检查，减少了系统API调用次数，提高了效率。

异步asynchronize

应用程序aio_read->系统调用->内核返回调用状态->内核返回注册状态->内核数据未准备好->应用程序继续执行自己任务->数据准备好->内核将数据拷贝到用户空间从aiocbp到aio_buf->通过aio_read注册的信号通知应用程序
